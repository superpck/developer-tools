URL Checking: rate limit & injection tests

Run quick, browser-based smoke tests against an endpoint before release: burst/rate-limit behavior, common injection payloads, CORS configuration, and recommended security response headers.

Use responsibly: only test URLs you own or are authorized to test. Requests run directly in your browser; the rate-limit test is capped at {{ maxRequests }} requests with up to {{ maxConcurrency }} concurrent connections to avoid accidentally overloading a production service.

Query string parameters (e.g. ?id=1) are auto-detected as injection targets. Include {{ '{{payload}}' }} anywhere in the URL to control exactly where payloads are inserted instead.
